# CineSense data-source research

**Reviewed:** 2026-11-25. This is an engineering comparison, not legal advice. Recheck the linked provider terms immediately before requesting, retaining, transforming, displaying, redistributing, or commercially using data. No source data has been downloaded into this repository.

## Initial source strategy

1. **Primary candidate:** TMDB API for app-facing movie metadata only after an API account accepts the terms and the project confirms its non-commercial scope, attribution placement, permitted caching and derived-use rules. Add the requested TMDB notice/approved mark to an About/Credits area before displaying API-sourced content.
2. **Research candidate:** MovieLens 32M as a pinned offline recommendation-evaluation set only if its non-commercial research conditions fit the intended use. Do not bring its 87k movie rows into the user catalog merely to increase coverage.
3. **Structured enrichment candidate:** Wikidata for individual sourced facts and external-ID matching. Preserve entity ID, statement/qualifier/reference information and retrieval time; a missing statement means unknown, not false.
4. **Optional plot research:** CMU corpus only after reviewing its ShareAlike obligations and source lineage. Keep its plot text and outputs distinct from TMDB content so rights and provenance do not become ambiguous.

The brief's desired initial range of 5,000–10,000 movies is a target only where licensed data coverage permits. Do not fabricate records or select a dataset solely to hit a count. With no API credential, local mode must identify its dataset source and license; absent an approved seed, it should show an honest empty state rather than invented recommendations.

## Phase 3 implementation and live-use gate

The Python data platform implements TMDB discover, search, details, credits, genre list, and movie external-ID operations. See [data-platform usage and policy](data-platform/README.md). Its CLI defaults to dry-run; database writes require `--execute` plus separate explicit terms, attribution, non-commercial scope, source-policy, and persistence acknowledgements. This is an operator-controlled gate, not a legal conclusion. Review current [TMDB terms](https://www.themoviedb.org/documentation/api/terms-of-use), [authentication](https://developer.themoviedb.org/docs/authentication-application), [discover](https://developer.themoviedb.org/reference/discover-movie), [movie details](https://developer.themoviedb.org/reference/movie-details), [credits](https://developer.themoviedb.org/reference/movie-credits), [genres](https://developer.themoviedb.org/reference/genre-movie-list), [rate limiting](https://developer.themoviedb.org/docs/rate-limiting), and [FAQ/attribution](https://developer.themoviedb.org/docs/faq) before real requests and especially before storage/redistribution. API-key possession is not treated as permission. No real TMDB records have been loaded as part of this phase.

## Provider contract

The Phase 3 provider boundary covers discovery, search, details, credits, genre metadata, external IDs, page state, retry/rate behavior and source/terms metadata. Future adapters can implement the same interface; no protected-site scraping is allowed. Normalized claims keep provider source records, evidence locators, retrieval timestamps and provider-vs-model provenance. Cross-source fuzzy matches are scored and kept in review; they are never merged automatically.
